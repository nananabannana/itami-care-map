# 医療機関情報の調査・登録手順

全国47都道府県へ調査を広げるときの手順。**推測で登録しない**ことを最優先にする。

## 1. 調査の単位

- 1回の調査は「1つの地方（例：中部）」または「5〜15施設」を目安にする
- 調査結果は `supabase/seed/YYYY-MM-DD_<地域や内容>.sql` として1ファイルにまとめ、PRで差分を確認してから Supabase の SQL Editor で実行する
- 実行後は管理画面（`/admin/review`）で1施設ずつ承認する

## 2. 候補の探し方（管理画面を使う）

### 2-1. ナビイから掲載候補を取り込む（`/admin/import/navii`）
1. 厚生労働省「医療情報ネットのオープンデータ」から、病院・診療所の「施設票」と「診療科・診療時間票」をダウンロードする（ZIPのままでよい。文字コードは UTF-8 BOM）
2. 4ファイルを選び「読み込んで婦人科系を抽出」。婦人科・産婦人科・産科のある施設だけがこの端末の中で抽出される
3. 都道府県を選び「ドライラン」。新規／更新候補／既存の掲載施設と一致／重複の可能性 が一覧で出る（まだ保存しない）
4. 内容を確認して「掲載候補として保存する」。すべて「未確認」の候補になり、公開はされない
5. 間違えたら「取り込み履歴」から取り消せる（作業済みの候補は残る）

ナビイのオープンデータに **電話番号・郵便番号は含まれない**。重複判定は「ナビイID → 住所＋名称 → 位置（100m以内）＋名称 → 名称のみ（要確認）」の順。既存の掲載施設と一致したものは新規登録せず、差分を「更新候補」として持つ（掲載施設は自動では変わらない）。

### 2-2. JALAの無痛分娩情報を取り込む（`/admin/import/jala`）
- 都道府県別の一覧ページ（`jalasite.org/area/…_all`）だけを、4秒間隔で取得する。各施設の詳細ページは取得しない
- 名称・郵便番号・住所・URL・電話番号を保存し、掲載施設・候補とひも付ける（名称だけの一致はひも付けない）
- 表示は掲載施設の「分娩・無痛分娩」欄だけ。**婦人科処置の麻酔対応の根拠には使わない**
- 候補の電話番号・郵便番号が空欄なら、JALAの値で補う

### 2-3. 候補を確認して掲載する（`/admin/candidates`）
1. 候補の詳細から公式サイトを開き、処置ごとの麻酔・鎮痛の記載を探す
2. 見つかったら「根拠を追加」（処置名・麻酔方法・対応状況・公式URL・原文・確認日・確認方法）。状態は自動で「公式情報確認済み」になる
3. 記載が無ければ「公式サイト確認待ち」や「掲載対象外」にする（メモに理由）
4. 確認できた候補を「掲載可能」にして「下書きへ送る」（1回20件まで）
5. 「公開前レビュー」で承認すると公開。**麻酔・鎮痛の根拠が無い施設はDBが承認を拒否する**

## 2'. 候補の探し方（公式サイトの調べ方）

1. 厚生労働省「医療情報ネット（ナビイ）」で、婦人科・産婦人科のある医療機関を地域ごとに洗い出す
2. 各医療機関の公式サイトで、次のページを探す
   - 婦人科の手術・検査の説明ページ（子宮鏡、中絶、IUD、内膜検査など）
   - 患者向けの説明文書・クリニカルパス（PDF）
   - よくある質問、麻酔科のページ
3. 麻酔・鎮痛の方法が **処置名と一緒に** 書かれているものだけを登録対象にする

## 3. 登録のルール

| 状況 | 登録のしかた |
| --- | --- |
| 公式ページに「○○は△△麻酔で行います」とある | 処置×麻酔方法を `available`、確度 `A`、根拠の原文を短く引用 |
| 複数の方法から選ぶと書いてある | 方法ごとに1行ずつ。条件に「〜と選択」と書く |
| 「希望により」「痛みが強い場合は」など条件付き | `available` にして、条件欄にその条件を書く |
| 通常は麻酔なしと書いてある | 麻酔方法 `none`（麻酔を使用しない）。検索の順位付けには使われない |
| 「痛みが心配な方はご相談ください」だけ | `consultation`、確度 `C` |
| 電話・フォームで確認した | 確度 `B`。出典に確認日と部署（個人名は書かない） |
| 手術・診療実績はあるが麻酔の記載がない | 施設としては登録せず `research_candidates` に入れる |
| ページが見られない・公開停止中 | `research_candidates` に入れ、状況をメモ |

### 混同しないこと

- **子宮鏡検査**（`hysteroscopy`）と **子宮鏡下手術**（`hysteroscopic-surgery`）は別の処置
- **ラミナリアなどの頸管拡張**（`cervical-dilation`）と、その後の手術は別の行にする。何の術前処置か（中絶・子宮鏡下手術など）を条件欄に書く
- **無痛分娩**（`labor`）の対応を、婦人科の処置の麻酔対応として扱わない
- **麻酔科の認定施設**であることだけで、処置の麻酔対応を登録しない
- 調査メモと公式ページの記載が違うときは、**公式ページの記載を登録**し、違いを出典の `notes` に残す

### 日付

- `verified_at`：公式ページを実際に開いて照合した日
- `document_date`：資料に書かれた作成日・更新日・掲載日。書かれていなければ「記載なし」
- `review_due_at`：自動で確認日＋6か月。資料が古い・日付がない場合は確認日当日にして「要再確認」にする

## 4. 登録SQLの書き方

`supabase/seed/2026-10-30_first_survey.sql` をひな形にする。

- 施設ごとに `do $$ ... $$;` のブロックを1つ作る
- 先頭で同じ `slug` があればスキップする（何度実行しても重複しない）
- `is_demo = false`、`is_published = false`、`review_status = 'draft'` で登録する
- `slug` は英小文字とハイフン（例：`chiba-aoba-municipal-hospital`）。デモデータの `demo-` で始めない

実行前にローカルで検証する：

```bash
npm run check:sql   # migrations と seed を PGlite（WASM版PostgreSQL）で実行して制約を確認
```

## 5. 公開前レビュー（管理者）

`/admin/review` で、施設ごとに次を確認してから「承認して公開する」を押す。

1. 出典リンクを開き、根拠の原文と登録内容（処置・麻酔方法・条件）が一致する
2. 推測で補った項目がない
3. 資料の日付が古い・記載なしの場合は、現行の運用か確認した（必要なら医療機関に問い合わせて確度Bで追加）
4. 住所・電話番号が公式サイトと一致する

承認・差し戻し・非公開の操作は `audit_logs` に記録される。
